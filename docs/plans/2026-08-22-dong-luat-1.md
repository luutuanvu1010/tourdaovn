Mọi task đều chịu các ràng buộc này; không nhắc lại trong từng task.

- **Cổng sau mỗi task:** `npm run check` (astro check) phải **0 lỗi 0 cảnh báo**. Task nào chạm validator thì thêm `npm --prefix scripts run gate:all`.
- **Baseline `gate:all` lúc bắt đầu là 5 đỏ** — `jsonld-post` I6, `r3-r4-post`, `governance-post` S24, `control-registry-gate`, `deferred-gate`. Cả 5 là nợ dữ liệu cũ, **không** phải do kế hoạch này. Đỏ thứ 6 xuất hiện là do task đang chạy.
- **Commit sau mỗi task**, không gộp. Thông điệp commit không dấu tiếng Việt (theo lệ repo).

```ts
 * Luật 1 (06-BINDING_MAP §6) — một thông tin, một vùng, một lần.

 * Tầng A (task này) — LẶP VÙNG: một field xuất hiện ở nhiều vùng hơn mức §3.1

 * tự ghi "bộ kiểm g3 không đọc". Hệ quả đo được ngày 2026-08-22: 44/58 trang

import { readFileSync, writeFileSync, mkdirSync, readdirSync, statSync } from 'node:fs'
import { dirname, resolve, relative } from 'node:path'
import { fileURLToPath } from 'node:url'

const __dirname = dirname(fileURLToPath(import.meta.url))
const REPO_ROOT = resolve(__dirname, '..', '..')
const BINDING_MAP = resolve(REPO_ROOT, 'docs', 'core-specs', '06-BINDING_MAP.md')
const DIST = resolve(REPO_ROOT, 'dist')
const REPORT_DIR = resolve(REPO_ROOT, 'scripts', 'reports')

/**
 * Lớp phiên dịch tên vùng: §3.1 gọi vùng bằng tiếng Việt, HTML gắn id ngắn.
 * Đây KHÔNG phải nguồn sự thật thứ hai về "field nào ở vùng nào" — nó chỉ
 * chuẩn hoá CÁCH VIẾT. Bằng chứng: mọi tên vùng đọc được từ §3.1 mà không có
 * trong bảng này đều làm validator đỏ (xem ktraVungLa).

const ALIAS: Record<string, string> = {
  'huy hiệu hero': 'hero-badge',
  'hero': 'hero',
  'breadcrumb': 'breadcrumb',
  'thông tin nhanh': 'fact-strip',
  'thanh dính': 'sticky-bar',
  'khối hành động': 'action-block',
  'thẻ bản đồ': 'map-card',
}

/** Vùng cũ, chưa có trong §3.1, sẽ biến mất ở Task 7. Tầng A vẫn đếm chúng. */
const VUNG_CU = new Set(['info-bar', 'info-card'])

function chuanHoa(s: string): string {
  return s.toLowerCase().replace(/\(.*?\)/g, '').replace(/[`*]/g, '').trim()
}

/** Đọc ma trận §3.1 → Map<field, Set<vùng>>. */
function docMaTran(): Map<string, Set<string>> {
  const doc = readFileSync(BINDING_MAP, 'utf-8')
  const m = doc.match(/### 3\.1[\s\S]*?\n(\|[\s\S]*?)\n\n/)
  if (!m) throw new Error('Khong doc duoc ma tran §3.1 trong 06-BINDING_MAP.md')
  const out = new Map<string, Set<string>>()
  for (const line of m[1].split('\n')) {
    if (!line.startsWith('|') || /^\|\s*-+/.test(line.slice(1))) continue
    const cells = line.split('|').slice(1, -1).map(c => c.trim())
    if (cells.length < 2 || cells[0] === 'Field') continue
    // Cột 0 có thể gộp nhiều field: "`a` · `b` · `c`"
    const fields = cells[0].split('·').map(f => f.replace(/[`*]/g, '').trim()).filter(Boolean)
    const vungs = new Set<string>()
    for (const cell of cells.slice(1)) {
      if (cell === '—' || !cell) continue
      for (const phan of chuanHoa(cell).split('+')) {
        const key = phan.replace(/,.*$/, '').trim()
        const id = ALIAS[key]
        if (id) vungs.add(id)
        else if (key.startsWith('mục') || key.startsWith('dòng')) vungs.add('section')
        else vungs.add(`?${key}`)   // không nhận ra → để lộ ra, ktraVungLa bắt
      }
    }
    for (const f of fields) {
      const k = f === 'giá' ? 'gia' : f
      out.set(k, new Set([...(out.get(k) ?? []), ...vungs]))
    }
  }
  return out
}

function ktraVungLa(maTran: Map<string, Set<string>>): string[] {
  const la: string[] = []
  for (const [field, vungs] of maTran)
    for (const v of vungs) if (v.startsWith('?')) la.push(`${field} → ${v.slice(1)}`)
  return la
}

function moiTrangHtml(dir: string, acc: string[] = []): string[] {
  for (const e of readdirSync(dir)) {
    const p = resolve(dir, e)
    if (statSync(p).isDirectory()) moiTrangHtml(p, acc)
    else if (e === 'index.html') acc.push(p)
  }
  return acc
}

/** Gom (field, vùng) của một trang. Vùng là data-region gần nhất bao ô đó. */
function docTrang(html: string): Map<string, Set<string>> {
  const out = new Map<string, Set<string>>()
  const rx = /data-region="([a-z-]+)"|data-field="([A-Za-z]+)"/g
  let vungHienTai = ''
  let m: RegExpExecArray | null
  while ((m = rx.exec(html))) {
    if (m[1]) { vungHienTai = m[1]; continue }
    const field = m[2]
    if (!vungHienTai) continue
    if (!out.has(field)) out.set(field, new Set())
    out.get(field)!.add(vungHienTai)
  }
  return out
}
```

- [ ] **Bước 2: Bốn entity §3.1 chưa khai**

`06` §3.1 chỉ khai **bốn** entity (Điểm tham quan, Địa danh, Trải nghiệm, Tour). Bốn template còn dùng hai component cũ mà **không** có hàng trong ma trận: `RestaurantDetail`, `SpecialtyDetail`, `EventDetail`, `LodgingDetail`.

Chạy: `grep -ln "InfoBar\|InfoCard" src/components/*.astro` — mọi file hiện ra phải được xử.

Với bốn entity này, quy tắc là: **giữ nguyên bộ field đang có, nhưng dồn về đúng một vùng `FactStrip`.** Đây là chỗ Luật 1 vẫn áp (luật ở §6 nói "mọi field hiển thị của trang chi tiết"), còn ma trận §3.1 thì chưa liệt kê — nên không có vùng nào để đối chiếu, chỉ có ràng buộc "một vùng".

Cụ thể, gộp `infoBarItems` và `sidebarRows` thành một mảng `facts` **loại trùng theo `field`**, giữ ô đầy đủ hơn khi hai bên cùng có một field:

| Template | Field vào `facts` sau khi gộp |
|---|---|
| `RestaurantDetail` | `servesCuisine`, `openingHours`, `address`, `telephone` |
| `SpecialtyDetail` | `specialtyType`, `originNote`, `season` |
| `EventDetail` · `LodgingDetail` | giữ nguyên bộ đang có, loại trùng theo `field` |

Rồi ghi một phiếu drift vào `docs/DRIFT_LOG.md`:

